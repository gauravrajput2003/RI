introductory
This document defines the description of the application layer interface protocol for the
vehicle GPS locator, positioning service platform. This interface protocol only applies to the
interactive communication between the server platform and the positioning terminal.

3. Ground rules
1. The GPRS connection is successfully established and the first login packet is sent to the
server. If a response packet is received from the server within 5 seconds, the connection is
considered to be normal and the positioning information (GPS, LBS packet) will be sent, and a
status packet will be sent after 3 minutes to confirm the normal communication at regular
intervals;
2. When the GPRS connection is not successfully established, the terminal cannot send the
login information packet. When the GPRS connection fails 3 times, the terminal starts the timed
restart function for 20 minutes. If the terminal successfully establishes a connection with the
server and receives a packet from the server in response to the login information packet sent by
the terminal within 20 minutes, the timed restart function is turned off and the terminal is not
restarted, otherwise the terminal is restarted automatically after 20 minutes;
3. The server needs to return the response packet to the terminal after it receives the login
information sent by the terminal. If the terminal does not receive the return packet from the server
for more than 5 seconds after it sends the login information packet or the status information
packet, it considers that the current connection is established abnormally, starts the function of
GPS positioning data retransmission, disconnects the current GPRS connection, establishes a
new GPRS connection and sends the login information packet;
4. The connection is judged to be abnormal, repeat 3 times to establish the connection after
sending the login information packet or the status information packet can not receive the data
packet of the server response, the terminal starts the timed restart function, and the timing time
is 10 minutes, if the terminal successfully establishes the connection with the server and receives
the data packet of the server response within 10 minutes, then the timed restart function is
closed, and the terminal is not restarted, or the terminal will be restarted automatically after 10
minutes. Otherwise, the terminal will restart automatically after 10 minutes;
5. After the connection is normally established, the terminal sends a combined GPS and
LBS information packet to the server at regular intervals after the GPS information is changed,
and the server can set the default sending protocol by command;
6. To ensure the validity of the connection, heartbeat packets are sent to the server at fixed
intervals, and the server returns a response packet to confirm;
7. For terminals without registered IMEI numbers, the server should reply to the login request
response and heartbeat packet response, and do not disconnect directly. (If you disconnect
directly or do not reply, it will cause the terminal to reconnect constantly and the GPRS traffic will
be consumed seriously).

4.5. information sequence numbers
The sequence number of the first GPRS data (including status packets and GPS, LBS,
etc. packets) sent after power on is '1', and the sequence number of every data (including
status packets and GPS, LBS packets) sent after that is automatically increased by 1.
4.6 Error checking
The terminal or server can use the check digit to determine whether the received
information is wrong or not. In order to prevent data errors during transmission, an error check
is added to prevent data misuse, which increases the safety and efficiency of the system. The
error check code adopts the CRC-ITU calibration method.
The CRC-ITU value of the data in the part of the protocol body from the "packet length" to
the "message sequence number" (including the "packet length", "message sequence number",
"packet length", "message sequence number" and "message sequence number"). ) in the
protocol body from "Packet Length" to "Message Sequence Number" (including "Packet
Length" and "Message Sequence Number").
If the receiver receives a message with a CRC error in the calculation, it ignores it and
discards the packet.

5.2.1.5. Number of satellites involved in positioning
1Byte converted to binary is 8Bit, the first 4Bit is the length of the GPS information, the last
4Bit is the current number of satellites of the device, the maximum value of the number of
satellites is 15, if more than 15, then 15 will be reported.
Note: The length includes the 1Byte occupied by itself.
Example: A value of 0xCB means that the length of the GPS message is 12 and the
number of satellites involved in the positioning is 11.
5.2.1.6. latitude
Occupies 4 bytes and represents the latitude value of the location data. The value ranges
from 0 to 162000000, indicating the range of 0 degrees to 90 degrees, and the conversion
method is as follows.
Convert the latitude and longitude values output from the GPS module into decimal

5.2.1.7 Longitude
Occupies 4 bytes and represents the longitude value of the positioning data. The value
ranges from 0 to 324000000, indicating a range of 0 degrees to 180 degrees.
The conversion method is the same as that for latitude.
